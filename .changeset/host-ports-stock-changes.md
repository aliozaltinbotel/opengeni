Stock changes from the host token, re-authentication and host port work, which apply to every managed deployment whether or not a host binds a port. Migration 1014 is required for every managed deployment: every password and Google/GitHub sign-in now writes `auth_session_authentications`, and sign-in-method changes now read their five-minute freshness from those events instead of the session's creation time. Freshness is therefore stricter: a native-app device session is never fresh on its own (it carries the approving session's authentication), and a session created by an email-verification link records no authentication, so it must sign in again (or re-authenticate with `POST /v1/auth/reauthenticate`, where a host token audience or TOTP is configured) before changing sign-in methods. During the rolling gap, a session signed in on a previous-binary replica has no recorded authentication, so it can neither change sign-in methods nor mint a host token until the person signs in again or re-authenticates on an upgraded replica; this fails closed and ends when the rollout completes. `/v1/auth/host-token`, `/v1/auth/reauthenticate` and `/v1/auth/totp/*` now answer JSON `404` refusals (`HOST_TOKEN_DISABLED`, `REAUTH_DISABLED`, `TOTP_DISABLED`) when their feature is off, instead of Better Auth's catch-all. The web app always has the new `/reauthenticate?return=<path>` page, and `POST /v1/auth/reauthenticate` is always routed; it re-authenticates only once a host token audience or TOTP is configured. Public-surface additions: the `@opengeni/contracts/organization-governance` export, the optional `meta` on tool catalog entries, and the optional `listResources`, `readResource` and `extensionMethods` members of `LocalMcpServerRegistration`.

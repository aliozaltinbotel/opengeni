A host that governs organizations can close every workspace and organization route its people do not need: with `OrganizationGovernancePort.memberRouteAccess: "allowlist"`, a person of a governed organization reaches `/v1/workspaces/:workspaceId/*` and `/v1/organizations/:organizationId/*` only through the governed allowlist, and every other route answers `403` with `details.code = "WORKSPACE_ROUTE_NOT_ALLOWED"` before its own checks. A person is a `user:` or `external_user:` subject with their own credential (browser session, native app credential, personal API key), or a host-minted person token (`principalKind: "human_session"` signed with the delegation secret). The host's service tokens, the worker's agent-attempt tokens, machine credentials and an organization key acting for a person (`asUser`) keep each route's own checks, and so do callers with no grant in the workspace or organization; MCP OAuth clients authenticate inside `/mcp` and get that route's own answer. The allowlist covers the workspace read, session list and create, the session routes whose operation is in `GOVERNED_MEMBER_SESSION_OPERATIONS`, the composer's reads, the workspace live streams, the inbox and notifications, documents, Knowledge, Skills, session feedback and artifact reads; not `/mcp` (the whole workspace tool gateway for a person's own credential) and no organization route. A guarded path that resolves no handler template is refused for a person (fail closed). New exports: `WORKSPACE_ROUTE_NOT_ALLOWED` (`@opengeni/contracts/organization-governance`); `GOVERNED_MEMBER_SESSION_OPERATIONS`, `GOVERNED_MEMBER_WORKSPACE_ROUTES`, `GOVERNED_MEMBER_ORGANIZATION_ROUTES`, `governedMemberRouteAllowed` and `governedRouteTable` (`@opengeni/api-router/app`), the last giving the decision for every mounted route so a host can generate its refusal tests. Without the opt-in nothing changes.

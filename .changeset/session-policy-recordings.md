The governed session policy gains an optional `recordings: "allowed" | "denied"` setting (migration 1019, an additive nullable column). Left out, it takes the default for the policy's source: `denied` for a governed organization's stored policy, `allowed` for stock (`sessionRecordingsAllowed`). When it denies, new recordings (meetings and dictation), their uploads, finalize, transcripts and live text, resumable transcription recordings and `POST /transcriptions` answer `403 SESSION_RECORDINGS_DENIED`; when it allows, they still follow the attachment switch (`403 ATTACHMENTS_DISABLED`). Existing recordings stay readable and editable, and the workspace client config reports voice input unavailable. A host sets it in the session-policy command; a command that leaves it out keeps the stored setting and keeps its old digest, and answers name it only once set, so existing host parsers read the governed default unchanged. The new host routine `opengeni_private.set_host_organization_session_recordings` ships with its runtime EXECUTE withheld for one release: until a later migration grants it, a command that names `recordings` answers `503 HOST_SESSION_POLICY_UNAVAILABLE` and records nothing. New exports: `OrganizationSessionRecordings`, `SESSION_RECORDINGS_DENIED`, `sessionRecordingsAllowed` (`@opengeni/contracts/organization-session-policy`), `SessionRecordingsDeniedError` and `requireOrganizationRecordingsAllowed` (`@opengeni/core`), `HOST_SESSION_RECORDINGS_ROUTINE` (`@opengeni/db`).
